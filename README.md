# LlamaBot — Local Intelligence Lab

A working showcase for local Ollama inference: document questions with inspectable evidence, a side-by-side model arena, and actual runtime telemetry. No framework, npm dependencies, CDN assets, or cloud inference.

## Run

1. Install Node.js 20+ and Ollama from https://ollama.com.
2. Start Ollama and install a model: `ollama pull llama3.2`.
3. In this directory, run `npm start`.
4. Open http://127.0.0.1:3000. Click the runtime status to reconnect after installing models.

Use `PORT=3001` as an environment variable if the default port is busy. In PowerShell: `$env:PORT = '3001'` then `npm start`. Opening index.html directly or using Live Server does not provide the local API proxy.

## A two-minute demo

- **Document intelligence:** load the fictional Northstar brief. Ask “What are the launch blockers, and who owns each one?” Inspect the retrieved excerpts and compare citations against the original text. Ask about pricing to test whether the model admits it is undecided.
- **Model arena:** install a second model, reconnect, select different models, and give both the same prompt. Both receive identical source excerpts and generation settings. They run sequentially to avoid loading two models simultaneously on small machines. Each response includes its own measured speed and latency.
- **Open conversation:** discuss anything with an installed model without document context.
- Export a JSON session containing prompts, outputs, source excerpts, settings, and metrics. Treat exports as private: they contain your data.

## What is real

Source retrieval uses browser-side BM25-style lexical ranking over overlapping 1,000-character passages. It does not require an embedding model. The top four matching passages are sent to Ollama; no matching passages means document mode abstains before inference. This is lexical retrieval, so paraphrases with no matching terms may miss relevant passages. Citations are generated by the model and must be checked; retrieval is not a factual correctness guarantee. Text files only: `.txt`, `.md`, `.csv`, `.json`, up to 1 MB each and 12 sources. Documents and conversation live in memory and reset on reload.

Streaming handles fragmented NDJSON and UTF-8. Output renders as text so document and model content cannot inject HTML. Stop cancels the local request and upstream inference connection. Failed and stopped runs are excluded from conversation context. Changing models or documents resets context. Document questions and model comparisons are independent single-turn runs so citations always refer to the current retrieved excerpts. Open conversation retains the last 12 messages.

Tokens/sec uses Ollama's `eval_count / (eval_duration / 1e9)`. Total duration comes from Ollama; first-token latency is measured in the browser and includes model load and prompt processing. The inspector shows the latest completed run, while each arena answer retains its own measurements. These are observations, not quality scores; model size, warm caches, hardware, and run order affect comparisons. Thinking-capable models may emit thinking before answer text; first-token measures the first answer token. The output cap is 768 tokens.

## Architecture and verification

`server.js` serves an explicit asset allowlist and proxies only `/api/tags` and `/api/chat` to `127.0.0.1:11434`. It binds to loopback, checks Host and Origin, caps request size, forwards cancellation, and restricts generation options. Keep this app local; it is not a public multi-user server. Use locally installed models; the interface discovers runtime models but cannot establish the provenance of a model alias.

`src/core.js` contains retrieval, streaming parsing, and metric conversion. `src/app.js` manages the workbench. `src/config.js` contains limits and the fictional demo source.

Each answer keeps its retrieved evidence, so older citations remain inspectable after subsequent questions. Source character offsets refer to the original text.

Run `npm test` for retrieval, fragmented streams, telemetry, proxy integration, and client workflow checks covering comparison fairness, source isolation, cancellation, errors, and export. Client checks use a DOM adapter; they do not verify browser rendering. API references: https://docs.ollama.com/api/chat and https://docs.ollama.com/api/tags.
